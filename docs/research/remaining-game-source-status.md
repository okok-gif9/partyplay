# وضعیت منابع بازی‌های باقی‌مانده

این یادداشت برای جلوگیری از جایگزین‌کردن یک نمای آزمایشی دیگر به‌جای بازی واقعی نگهداری می‌شود. معیار پذیرش پارتی پلی عبارت است از: مجوز روشن، رابط حرفه‌ای، بازی کامل، قابلیت بازی محلی یا ربات و استقرار بدون سرور در GitHub Pages.

| بازی | منبع بررسی‌شده | وضعیت | تصمیم |
|---|---|---|---|
| حکم | [nxrix/joke](https://github.com/nxrix/joke) | MIT و استاتیک است، اما رابط آغاز و تجربهٔ عملی آن برای معیار طراحی پارتی پلی مناسب نبود. | رد شد؛ انتقال داده نمی‌شود. |
| حکم | [farshadpasbani/Hokm](https://github.com/farshadpasbani/Hokm) | موتور قواعد و AI قدرتمند دارد، اما Flask/Python و مدل‌های AI لازم دارد؛ قابل‌استقرار روی GitHub Pages نیست. | برای نسخهٔ آیندهٔ دارای backend قابل‌بررسی است. |
| حکم | [matin-as/Online-hokm-game](https://github.com/matin-as/Online-hokm-game) | Unity و Photon؛ به runtime و سرویس آنلاین وابسته است. | برای GitHub Pages رد شد. |
| بکش‌وحدس‌بزن | [Arp-G/pictionary](https://github.com/Arp-G/pictionary) | رابط حرفه‌ای و MIT دارد، ولی همگام‌سازی، اتاق و بازی به Elixir backend وابسته‌اند. | برای GitHub Pagesِ استاتیک رد شد. |
| بکش‌وحدس‌بزن | [ShubhVaish1703/drawrush.io](https://github.com/ShubhVaish1703/drawrush.io) | رابط مدرن و MIT دارد، ولی Socket.IO، Express و سرویس AI لازم دارد. | برای نسخهٔ backend‌دار قابل‌بررسی است، نه انتقال استاتیک. |
| بکش‌وحدس‌بزن | [CrazyTim/tap-and-draw](https://github.com/CrazyTim/tap-and-draw) | MIT و استاتیک است، اما برای نقاشی روی کاغذ طراحی شده و بوم دیجیتال یا حدس‌زدن درون‌برنامه‌ای ندارد. | رد شد؛ جایگزین بکش‌وحدس‌بزن پارتی پلی نیست. |

## نتیجهٔ موقت

برای حکم و بکش‌وحدس‌بزن، منبع متن‌بازِ کامل، خوش‌طراحی، دارای ربات/چندبازیکنه و هم‌زمان قابل‌استقرارِ صرفاً استاتیک پیدا نشد. انتقال منبع ضعیف یا شکستن برنامهٔ وابسته به سرور، با خواستهٔ صریح کاربر برای «بازی واقعی و طراحی عالی» ناسازگار است؛ بنابراین تا زمان یافتن منبع مناسب، نسخه‌های موجود نباید با یک پوستهٔ ناقص جایگزین شوند.
