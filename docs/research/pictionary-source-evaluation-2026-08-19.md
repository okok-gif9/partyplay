# ارزیابی منابع بکش‌وحدس‌بزن

**تاریخ:** ۱۹ اوت ۲۰۲۶  
**معیار:** بوم نقاشی واقعی، گردش نوبت، واژه، حدس و امتیاز، مجوز روشن و امکان استقرار با GitHub Pages/Supabase بدون سرور خارجی.

| منبع | فناوری و مجوز | ارزیابی | تصمیم |
|---|---|---|---|
| [`Arp-G/pictionary`](https://github.com/Arp-G/pictionary) | React و Elixir/Phoenix؛ MIT؛ ۱۵۱ commit و رابط کامل با اتاق خصوصی/عمومی، دور، واژه، امتیاز و حالت تاریک. | از نظر تجربهٔ محصول حرفه‌ای‌ترین منبع بررسی‌شده است، اما منطق چندنفره به سرور Elixir و حافظهٔ ETS وابسته است. GitHub Pages نمی‌تواند آن را اجرا کند. | **رد برای انتقال مستقیم**؛ می‌تواند فقط مرجع طراحی برای مشخصات آنلاین آینده باشد. |
| [`jyang81/pictionary-react`](https://github.com/jyang81/pictionary-react) | React/Canvas با Rails و ActionCable؛ مجوز در صفحهٔ بررسی‌شده اعلام نشده. | بوم واقعی و حدس دارد، اما به backend جداگانه، Redis/ActionCable و سرور پایدار وابسته است؛ فهرست نقص‌های شناخته‌شده نیز دارد. | **رد**. |
| [`lukascode/puns`](https://github.com/lukascode/puns) | وب‌کلاینت و سرورهای متعدد؛ مجوز در صفحهٔ بررسی‌شده اعلام نشده. | ساختار اتاق و دورها دارد، ولی ذاتاً شبکه‌ای و دارای سرویس‌های جداگانه است؛ با استقرار استاتیک سازگار نیست. | **رد**. |

## نتیجه

در این مرحله هیچ منبع حرفه‌ای، دارای مجوز روشن و قابل اجرای مستقیم در GitHub Pages برای بکش‌وحدس‌بزن پیدا نشد. این بازی همچنان خارج از آرکید باقی می‌ماند. انتقال نسخهٔ حرفه‌ای آن فقط با یک پروژهٔ بومی جداگانه بر پایهٔ Supabase Realtime—نه یک نسخهٔ نمایشی—قابل بررسی است.
