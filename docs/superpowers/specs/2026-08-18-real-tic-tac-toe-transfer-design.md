# طراحی انتقال مستقیم دوز واقعی به پارتی پلی

## هدف

جایگزینی کامل صحنهٔ سادهٔ «دوز کلاسیک» با کد واقعیِ بازی متن‌باز [`ramazancetinkaya/tictactoe`](https://github.com/ramazancetinkaya/tictactoe) تحت مجوز MIT. خروجی باید تجربهٔ کامل منبع را—از انتخاب مهره و درجهٔ دشواری تا هوش مصنوعی، نشانگر نوبت، امتیاز، نتیجه و دور بعد—بدون بازنویسی موتور بازی ارائه کند.

## منبع و مجوز

منبع در قالب HTML، CSS و JavaScript بدون وابستگی است. کپی‌های منتقل‌شده باید شامل فایل `LICENSE` اصلی با حق‌نشر سازنده باشند. برای شفافیت، فایل `ATTRIBUTION.md` در کنار بازی منتقل‌شده، نشانی مخزن، نام سازنده، نوع مجوز و تغییرات مجاز انجام‌شده را ثبت می‌کند.

## معماری انتقال

کد منبع بدون تبدیل به منطق React در مسیر زیر قرار می‌گیرد:

```text
public/games/tic-tac-toe/
  index.html
  styles.css
  script.js
  LICENSE
  ATTRIBUTION.md
```

`index.html` بازی اصلی را از `styles.css` و `script.js` محلی بارگذاری می‌کند. React هیچ‌کدام از قواعد بازی، موتور ربات، state صفحه یا کد تصمیم‌گیری آن را بازنویسی نمی‌کند. یک کامپوننت میزبان React با نام `RealTicTacToe` بازی را در یک iframe داخلی نمایش می‌دهد؛ بنابراین بازی واقعی، با ظاهر و کنترل‌های اصلی خودش و بدون وابستگی بیرونی، داخل همان دامنه و همان انتشار GitHub Pages اجرا می‌شود.

## تجربهٔ کاربر

از کارت «دوز کلاسیک»، دکمهٔ **بازی با ربات** باید مستقیماً به صفحهٔ میزبان بازی منتقل‌شده برود. خود بازی منبع شامل انتخاب X/O، سختی آسان/متوسط/سخت، تابلوی ۳×۳، نشانگر تفکر ربات، امتیاز نشست، مودال برد/مساوی و شروع دور بعد است. محتوای ثابت رابط منبع به فارسی ترجمه می‌شود، اما ساختار، موتور و طراحی تعاملی آن حفظ می‌شود.

دکمهٔ **اتاق دوستان** هیچ تغییر نمایشی نمی‌گیرد و همچنان به لابی آنلاین Supabase دوز هدایت می‌کند. این تفکیک مانع آن می‌شود که یک بازی بومی محلی با منطق اتاق خصوصی موجود قاطی شود.

## مرز تغییرات مجاز

تغییرات فقط شامل موارد زیر است: مسیرهای دارایی برای اجرا در GitHub Pages، متون انگلیسی به فارسی، تعیین `lang="fa"` و `dir="rtl"`، فونت مناسب فارسی در صورت نیاز و سازگارکنندهٔ iframe. هیچ‌یک از منطق برد، حرکت ربات، انتخاب سختی، محاسبهٔ امتیاز یا کنترل‌های منبع بازنویسی نمی‌شوند.

## آزمون پذیرش

1. فایل‌های منتقل‌شده بدون شبکهٔ خارجیِ لازم برای موتور بازی بارگذاری شوند.
2. انتخاب نماد و هر سه دشواری ربات کار کند.
3. با یک حرکت کاربر، نوبت ربات نمایش داده شود و بازی پاسخ معتبر دهد.
4. برد، مساوی، امتیاز، دور بعد، بازنشانی و بازگشت به پارتی پلی قابل‌اجرا باشند.
5. مسیر «اتاق دوستان» دوز همچنان لابی آنلاین قبلی را باز کند.
6. `pnpm build` موفق شود و انتشار GitHub Pages بتواند بازی را از مسیر پایهٔ `/partyplay/` بارگذاری کند.

## موارد خارج از این انتقال

چندنفرهٔ هم‌زمان در خود منبع اصلی وجود ندارد و در این مرحله به بازی منتقل‌شده افزوده نمی‌شود. مسیر آنلاین Supabase پارتی پلی برای اتاق دوستان جداگانه حفظ می‌شود. مارپله یا هر بازی دیگر تا تکمیل، آزمون و انتشار دوز وارد این تغییر نمی‌شود.
