# پژوهش مافیا و بازی‌های بیشتر برای پارتی پلی

## موتورهای مافیا

| نامزد | شاهد فنی و مجوز | تناسب با مافیای فارسی پارتی پلی |
|---|---|---|
| [Open Mafia Engine][1] | Apache-2.0، ۳۶۶ commit، موتور Python رویدادمحور با GameBuilder، نقش‌ها و شروط برد قابل‌تعریف. | **بهترین موتور قواعد**. مدل نقش و گذار فازها باید در توابع PostgreSQL/Supabase بازنویسی شود؛ خود Python به GitHub Pages وارد نمی‌شود. |
| [Mafia 67][2] | MIT؛ React + TypeScript + Vite با اتاق خصوصی، نقش مخفی، چرخهٔ شب/روز، رأی، چت تیم مافیا و منطق سرورمحور. | **بهترین مرجع UI و جریان مدرن**. ساختارش بسیار نزدیک به پارتی پلی است، اما Firebase/Socket.IO/SQLite باید با Supabase جایگزین شود. |
| [deekstone/MafiaGame][3] | MIT، monorepo TypeScript با React/Vite، lobby/game، Socket.IO و مستندات جدا برای GameManager و socket events. | **بهترین مرجع قرارداد TypeScript**. لایه‌های اتصال و مدیریت بازی قابل مطالعه و اقتباس‌اند، ولی سرور Node نباید عیناً وارد پروژه شود. |
| [PlayMafia][4] | MIT؛ ۱۹ نقش، لابی، چت عمومی/خصوصی، چرخهٔ روز/شب، reconnect و ماژولارکردن نقش‌ها، اما Node/Redis/SockJS قدیمی است. | **غنی‌ترین مرجع نقش و تنظیمات**. فقط قواعد و ساختار داده؛ UI و زیرساخت قدیمی آن استفاده نمی‌شود. |
| [AshuferMorningstar/Mafia][5] | FastAPI/Socket.IO/React با گزینهٔ skip، چت خصوصی تیم‌ها و گذار روشن شب→روز→رأی؛ مجوز اعلام نشده است. | **مرجع رفتار محصول، نه کد قابل اقتباس** تا زمانی که مجوز روشن شود. |
| [AlecM33/Werewolf][6] | ۴۴ ستاره، ۸۲۸ commit و تجربهٔ اتاق/کارت/مدیر بسیار پخته، اما GPL-3.0 و برخلاف نیاز پارتی پلی، موتور نقش‌ها را اجرا نمی‌کند. | **مرجع UX و گردانندهٔ بازی، نه کد**. مجوز GPL استفادهٔ مستقیم را نامناسب می‌کند. |

## جمع‌بندی مافیا

موتور نهایی پیشنهادی یک اقتباس ترکیبی است: **موتور رویدادمحور Open Mafia Engine برای مدل‌سازی نقش‌ها و شروط برد** [1]، **جریان و صحنه‌های مدرن Mafia 67 برای لابی، کارت نقش، شب/روز، رأی و چت خصوصی** [2] و **الگوهای TypeScript/مدیریت نشست MafiaGame برای مرزبندی رابط و سرور** [3]. این ترکیب با مدل قبلاً تأییدشدهٔ پارتی پلی سازگار است: ظرفیت ۵/۷/۹، Godfather، Doctor با یک خودنجات، Detective با استعلام دو مرحله‌ای، معارفهٔ روز اول بدون رأی، رأی «هیچ‌کس»، واکنش به سخنران و راوی خودکار.

> تصمیم فنی: نقش و دستورات شبانه نباید از کلاینت قابل‌اعتماد باشند. Supabase RPC و RLS باید همچنان مرجع نهایی وضعیت باقی بمانند؛ هیچ Socket.IO، Redis، Firebase یا Python service جدیدی به GitHub Pages اضافه نمی‌شود.

| **آندرکاور / کلمهٔ مخفی** | [Undercover Word Game][7] | MIT | ۳ تا ۸ نفر، نقش‌مخفی، واژه‌های دوتایی، رأی‌گیری و برد ویژهٔ Mr. White؛ بسیار مناسب واژه‌های فارسی اختصاصی. |

| **آوالونِ فارسی** | [avalon-online][9] | مجوز مشخص نشده | مکانیک نقش‌مخفی تیمی بسیار جذاب است، اما فقط ایده/جریان بازی استفاده می‌شود؛ کارت‌ها، نام و محتوا مستقل طراحی می‌شوند. |
| **پلتفرم الگوی Supabase** | [Boardly][10] | MIT | خودِ بازی جدید نیست، اما دارای Guess the Spy، Alias، Connect Four و Yahtzee با الگوی state-authoritative و Supabase Realtime است؛ منبع معماری ایده‌آل برای ارتقای آنلاین بازی‌هاست. |
| **فهرست‌بازی** | [ListUp][11] | MIT | بازی کلمه‌ای با اتاق کددار، دورهای میزبان و امتیاز بر اساس دسته‌بندی؛ پیاده‌سازی فارسی کم‌هزینه و بسیار اجتماعی. |
| **کوئیز زنده** | [morrisonak/Trivia][12] | MIT | اتاق کددار، امتیاز سرعتی و حالت نمایش بزرگ؛ به مجموعهٔ گروهیِ فارسی تنوع خوبی می‌دهد. |
| **هزارراه / عبور از هزارتو** | [MazeCraze-Weblab-2024][13] | MIT | رقابت زندهٔ سبک با دورهای کوتاه، پاداش و مسیرسازی؛ برای افزودن مهارت/سرعت در کنار بازی‌های فکری مناسب است. |
| **بازی ملک و معامله** | [rayhankhilji/parkway][14] | MIT | موتور قوانین TypeScript و بازپخش دقیق؛ برای یک بازی استراتژی طولانی‌تر مناسب است، اما در موج بعدی قرار می‌گیرد. |

## نقشهٔ اقتباس مافیای فارسی

| الزام تأییدشدهٔ پارتی پلی | منبع اصلی برای الگو | تصمیم اقتباس |
|---|---|---|
| ظرفیت فقط ۵، ۷ و ۹ نفر | Open Mafia Engine [1] و Mafia 67 [2] | پیکربندی نقش‌ها در یک جدول ثابت Supabase برای هر ظرفیت؛ بازی فقط با ظرفیت کامل آغاز می‌شود. |
| Godfather، Mafia، Doctor، Detective و Citizen | Open Mafia Engine [1] و PlayMafia [4] | نقش‌ها داده‌محور هستند؛ Godfather در بازجویی اول Citizen و از بار دوم Godfather نمایش داده می‌شود. |
| روز اول معارفه، بدون رأی | Mafia 67 [2] | فاز `day_speaking` با صف سخنران و زمان اختیاری؛ شروع رأی فقط از روز دوم. |
| رأی مخفی، «هیچ‌کس» و منع رأی به خود | MafiaGame [3] و AshuferMorningstar/Mafia [5] | رأی فقط با RPC سرور ثبت می‌شود؛ گزینهٔ nobody و پیام «گل به خودی میزنی مشتی؟» حفظ می‌شود. |
| شب با تصمیم اختیاری مافیا، دکتر و کارآگاه | Open Mafia Engine [1] و Mafia 67 [2] | هر نقش می‌تواند هدف یا skip ارائه کند؛ سرور پس از اتمام/مهلت نقش‌های زنده، صبح را حل می‌کند. |
| چت کوتاه و خصوصی مافیا | Mafia 67 [2] و MafiaGame [3] | پیام‌ها با RLS و view خصوصی فقط به جناح Mafia می‌رسند؛ نقش هم‌تیمی تا پایان بازی فقط برای خود مافیا نشان داده می‌شود. |
| دکتر فقط یک‌بار خود را نجات دهد | مدل state داده‌محور [1] | پرچم `doctor_self_save_used` فقط روی سرور تغییر می‌کند و هدف self را پس از مصرف حذف می‌کند. |
| واکنش به سخنران | UI جدید پارتی پلی | رویدادهای 👍🏻، 👎🏻 و 🫵🏻 با شناسهٔ سخنران و روز ثبت و به همهٔ اعضا ارسال می‌شود. |
| کارت نقش سیاه/سفید/قرمز و راوی خودکار | Mafia 67 [2] به‌همراه هویت بصری پارتی پلی | منطق از موتور انتخابی و صحنه/متن از طراحی اصلی فارسی ساخته می‌شود؛ هیچ دارایی یا متن انگلیسی کپی نمی‌شود. |

**نتیجهٔ انتخاب:** برای نسخهٔ فارسی موردنظر، «موتور مفهومی» باید از Open Mafia Engine و قوانین متغیر آن گرفته شود؛ «جریان محصول و طراحی تعامل» از Mafia 67 و MafiaGame استخراج شود؛ و پیاده‌سازی واقعی داخل Supabase RPC/RLS پارتی پلی باقی بماند. این دقیقاً با معماری بدون سرورِ GitHub Pages و ساختار امنیتی نقش‌های مخفی سازگار است.
